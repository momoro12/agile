Программа измерений проекта
Тема: Система интеллектуального мониторинга и анализа инцидентов информационной безопасности (СМА ИБ)
1. Цели программы измерений
Согласно материалу лекции, программа измерений необходима для обеспечения решения задач предприятия. Для проекта СМА ИБ определены следующие цели:
Планирование проекта: Оценка трудозатрат на разработку модулей мониторинга и анализа.
Мониторинг выполнения проекта: Отслеживание прогресса разработки в реальном времени.
Обеспечение стратегических целей: Повышение производительности труда разработчиков, сокращение сроков создания системы и повышение качества ПО (критично для безопасности).
Поддержка потребностей менеджмента: Предоставление количественных показателей для принятия управленческих решений.
2. Методология формирования метрик (GQ(I)M)
Разработка метрик осуществляется в соответствии с методикой GQ(I)M (Goal Question Indicator Metric), описанной в лекции. Иерархия измерений строится от стратегической цели к конкретным числовым значениям.
3. Метрики эффективности процесса разработки (2 метрики)
Для оценки эффективности производственного процесса разработки системы выбраны следующие метрики из перечня употребительных видов метрик (Лекция 6):
3.1. Производительность труда (Productivity)
Данная метрика позволяет оценить объем кода, создаваемого командой за единицу времени, что важно для планирования сроков разработки модулей анализа инцидентов.
Стратегическая цель: Повысить производительность труда.
Изучаемый объект: Проект (разработка модулей СМА ИБ).
Измеряемый атрибут: Производительность труда на проекте.

3.2. Скорость обработки задач (Problem Resolution Rate — PRR)
Метрика оценивает скорость выполнения задач в рамках процесса разработки (например, задач в бэклоге спринта или исправление дефектов).

4. Метрики качества программного продукта (2 метрики)
Для оценки качества создаваемой системы безопасности выбраны метрики, характеризующие плотность дефектов, так как наличие ошибок в системе безопасности недопустимо.
4.1. Плотность ошибок в продукте (In Process Faults — IPF)
Общая метрика качества, показывающая количество дефектов, найденных до релиза, относительно размера кода.
Стратегическая цель: Повысить качество разрабатываемого ПО.
Изучаемый объект: Продукт (система СМА ИБ).

5. План реализации программы измерений
Согласно методике GQ(I)M, реализация программы измерений для проекта СМА ИБ включает следующие этапы:
Идентификация целей: Утверждение выбранных метрик (Productivity, PRR, IPF, PFD) руководством проекта.
Планирование процесса измерений:
Определение инструментов сбора данных (система контроля версий для LOC, трекер задач для PRR, система баг-трекинга для IPF/PFD).
Назначение ответственных за сбор данных (например, тимлид или отдел качества SQA).
Выполнение измерений:
Сбор данных в ходе спринтов/этапов разработки.
Проверка правильности собранных данных (валидация LOC, классификация ошибок).
Анализ и интерпретация данных:
Построение визуальных представлений (диаграмм) аналогично примерам из лекции (например, график PCE или гистограмма IPF).
Сравнение показателей с установленными целями (Goal).
Принятие решений по улучшению процесса (например, если PFD-Coding высок, усилить код-ревью).
